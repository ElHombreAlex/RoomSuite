# Mac installer

RoomSuite supports Apple silicon and Intel Macs running macOS 14 or later. Download the matching disk image from the latest release: `RoomSuite-macOS-arm64.dmg` for Apple silicon or `RoomSuite-macOS-x64.dmg` for Intel. Open the image and drag RoomSuite into Applications. The app contains its Node.js runtime, MCP dependencies and headless Chromium; it does not need Git, Node or npm to be installed separately.

The app is unsigned and is not notarized. When macOS blocks its first launch, open **System Settings → Privacy & Security**, review the warning, and use **Open Anyway**. See [Apple's instructions](https://support.apple.com/guide/mac-help/open-a-mac-app-from-an-unidentified-developer-mh40616/mac). Do not disable Gatekeeper globally. The release checksum detects corruption but does not verify the publisher.

Open RoomSuite from Applications and leave the launcher window open while working. It starts a local server and opens the suite in your browser. Closing the window stops the server. **MCP setup** copies JSON or Codex TOML configuration for the bundled runtime and browser; add it to your agent's own settings and restart the agent. The app does not edit those settings. If you move the app, update the copied paths.

The server listens on `127.0.0.1:8090` by default and has no built-in login. Camera, microphone, screen capture, media formats and exports depend on browser support and macOS permissions. For access from other devices, follow the protected access guidance in the [main README](../README.md#use-it-on-other-devices).

Projects, shared files, notes and the MCP workspace are stored under `~/Library/Application Support/RoomSuite`. Close RoomSuite before backing up or replacing the app. Updating means replacing the app in Applications; removing the app leaves this data folder in place. The app does not update itself.

For advanced use, `CLIPROOM_PORT` and `ROOMSUITE_APP_DATA` can be set in the launching environment. The MCP configuration generated by the launcher reflects those settings. A script can export the JSON configuration to a new file using `RoomSuite.app/Contents/MacOS/RoomSuite --export-mcp-config /path/to/new-config.json`; the parent must exist, and an existing file is not overwritten.

## Build and test

Build from a clean checkout on a Mac of the target architecture with Xcode command-line tools, Node.js 20 or later, npm and internet access:

~~~sh
npm ci --prefix mcp
bash macos/build-installer.sh
bash macos/smoke-installer.sh dist/RoomSuite-macOS-arm64.dmg  # use x64 on Intel
~~~

The build stages the application without local data, bundles the current Node runtime, installs the matching Playwright headless Chromium, and creates a disk image under `dist/`. It refuses to overwrite an existing image. The smoke test mounts the image, copies the app to a path containing spaces, verifies the launcher, configuration, browser and MCP workflows, and checks that data survives a restart. CI runs the build and checks separately on Intel and Apple silicon Macs. The build is not signed or notarized.
