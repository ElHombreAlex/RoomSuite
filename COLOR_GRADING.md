# Shared color and portable looks

PixelRoom and Cliproom share editable color controls. Select an image layer or picture clip and use the existing brightness, contrast and saturation controls. **Advanced color** adds exposure, temperature, tint, highlights, shadows, whites, blacks and vibrance; **Creative grading** opens curves, hue ranges, tonal color wheels, LUTs and finishing effects. Look strength scales the adjustments, while **Enable color adjustments** bypasses them without deleting values. Before/after and split comparison affect the selected item's editor preview, not exports.

Under **Looks & presets**, save the current values as a new local preset, search by name or tag, import or download a `.roomgrade` file, or exchange one through Shared files. Saving creates a separate preset; projects keep their own editable copy. Cliproom applies a look to the selected clip or explicitly to its track, up to 100 clips. Existing color and finishing-effect keyframes remain and may override base values. Undo and redo cover parameter and preset changes.

Browser-saved looks live in that browser's local storage and are not automatically synchronized or included in a server backup. Export them or save them to Shared files for other devices. FilesRoom's **Open in…** can import a shared `.roomgrade` into either editor. A preset contains adjustments, not source media.

## Format and processing

`.roomgrade` files are UTF-8 JSON, at most 2 MiB. Version 1 presets remain readable; neutral creative settings can still be written as version 1. Version 2 uses `schema_version: 2` and `color_pipeline_version: 2` and includes an editable `look`. Both versions have the `roomsuite.color-preset` format, a name, optional description and tags, primary `adjustments`, and a reserved empty `effects` array. Unsupported fields, versions, nonempty `effects`, invalid numbers, malformed files and oversized data are rejected. Presets do not execute code or refer to external files. Names have at most 100 characters, descriptions 500, and tags 12 entries of at most 40 characters each.

Primary adjustments default to zero. Exposure is −2 to +2 stops; brightness, contrast, saturation, temperature, tint, highlights, shadows, whites, blacks and vibrance are −100 to +100. Strength is a separate per-layer or per-clip value from 0 to 100 and is not stored in the preset. A version 2 look contains:

- Master, red, green and blue curves, each with five output values from 0 to 1 at fixed inputs 0, 0.25, 0.5, 0.75 and 1, with linear interpolation.
- Red, yellow, green, cyan, blue and magenta HSL ranges; hue is −30 to +30 degrees and saturation and luminance are −100 to +100.
- Shadows, midtones and highlights color wheels, each with a six-digit color and amount from −100 to +100.
- Optional embedded 3D LUT, grain 0–100 with an integer seed, vignette −100 to +100 and sharpening 0–100.

The `.cube` importer supports 3D tables from 2³ to 33³, optional quoted `TITLE`, `DOMAIN_MIN` and `DOMAIN_MAX`, and comments. Entries are ordered with red varying fastest, followed by green and blue, and are sampled with trilinear interpolation. A `.cube` is a color transform, not a complete RoomSuite preset: importing it embeds its table in the current look; exporting a `.roomgrade` also preserves the other settings. 1D LUTs, combined 1D/3D files and unsupported directives are rejected. Both the input file and exported preset are limited to 2 MiB. Cliproom projects also have a 2 MiB request limit, and embedding the same large LUT on many clips can exceed it; use a smaller LUT or fewer clips.

The canonical order is: browser decode → exposure, approximate temperature/tint, tonal corrections and vibrance → master and channel curves → HSL ranges → tonal wheels → 3D LUT → vignette and deterministic grain → sharpening → the existing Canvas brightness, contrast and saturation filters → layer/clip compositing and output. Alpha is preserved. These creative controls are not calibrated camera or color-science tools. Browsers and codecs handle decoding; there is no explicit ICC profile preservation, HDR, RAW or wide-gamut pipeline, and video color metadata is not guaranteed to survive. Use ordinary sRGB images and SDR/Rec.709 video and visually check the result.

PixelRoom limits interactive advanced-color processing to 2048 pixels on the long edge to reduce memory use; export uses source resolution. Cliproom evaluates source-time keyframes before grading; speed, trims, moves and splits keep them attached to the source. Fades and transitions are composited after grading. Primary color controls, grain, vignette and sharpening can be keyed individually. Under a picture keyframe's **Advanced color keyframes**, capture the current curves, HSL and wheels; capture an earlier look before changing the clip controls to define both ends of a transition. Numeric settings interpolate linearly, as do the sRGB channels of wheel colors. LUTs stay fixed on the clip. Advanced color grading and color keyframes use Cliproom project version 5, which earlier versions cannot open; plain compatible projects remain version 4. Pixel scaling and video compression can produce small differences. The automated advanced-look scenario allows up to 1 RGB level between PixelRoom UI and MCP image export, 15 for the sample Cliproom preview and 25 for encoded WebM; these thresholds describe test samples, not universal color accuracy.

The shared CPU transform is optional: neutral clips retain the existing fast Canvas path. Cliproom's **Fast color preview** reduces the long edge of the graded intermediate to at most 480 pixels during editing. It can soften detail and change grain or sharpening in the preview; real-time and every-frame exports still grade at the normal output size. The setting is browser-local and does not change the project. Heavy grades can stutter at full resolution. Choose **Every frame** in the export dialog to render a WebM frame by frame on the RoomSuite server; it can take substantially longer and needs the optional rendering dependencies. A two-track moving-video comparison against 2.5, including measured output frame counts, reproducible instructions and limitations, is in [PERFORMANCE.md](PERFORMANCE.md). GPU/worker acceleration, physical constrained-device testing, HDR and multi-codec color certification remain work to do.

## MCP and compatibility

`roomsuite_preset_list`, `roomsuite_preset_get` and `roomsuite_preset_create` manage built-ins or workspace files. `roomsuite_lut_inspect` validates a workspace `.cube`. `roomsuite_preset_preview` returns a bounded before/after image or up to six video-frame pairs, plus objective mean RGB values. The preview resizes before grading, so grain and sharpening can differ at export resolution. `pixelroom_edit`, `pixelroom_apply_preset`, `cliproom_apply_preset` and `cliproom_render` accept a preset or inline adjustments and creative look; `lut_path` embeds a workspace LUT and `remove_lut` removes it. Use existing Shared files upload/download tools to exchange presets. Revision-checked project edits reject stale changes.

Existing 2.5 projects without `colorGrade` load with neutral creative values, full strength and grading enabled. PixelRoom embeds the shared assets in `dist/` for standalone use; tests check equality with `cliproom/public/`. After changing a shared file, copy `color-look.js`, `color-grade.js`, `color-grade-ui.js` and `color-grade.css` into `PixelRoom/dist/` and run the tests. Graded PixelRoom projects use version 2 and graded Cliproom projects use version 5, so older editors reject them instead of silently dropping the look. Keep a backup before downgrading. Both editors support a regional mask as described below.

## PixelRoom local color region

Each image layer can have one editable color-region mask. Opaque or white mask areas receive that layer’s current grade; transparent or black areas keep the original appearance, with partial opacity blending between them while preserving the source alpha. Paint or import a region in the Isolate panel, edit the grade in the Edit panel, and remove the region to apply the grade to the whole layer. The region can coexist with a background cutout and is stored in version 2 `.pixelroom` projects. It is not part of `.roomgrade` presets. Both preview and image export apply the mask; the smaller editing preview can soften fine edges.

## Cliproom static color region

Select a picture clip, open **Color region** in the inspector and import a PNG, JPEG or WebP image with the same aspect ratio as the source. Choose brightness or transparency as the mask channel. White or opaque areas receive the clip’s current grade; black or transparent areas remain unchanged, with partial values blending the two. The mask follows the picture through its crop, transforms, trims, speed changes and splits; it is static and does not track moving objects. Replace or remove it at any time, and use undo/redo. A mask is embedded in the version 5 project, not in the preset or source media. Inputs are limited to 20 MiB and 40 megapixels, then reduced to at most 1,024 pixels per side. A project supports up to 16 distinct masks and four megapixels of masks, subject to the 2 MiB project save limit. Preview, realtime export and offline export share the same region compositing. Fast preview may soften its edges. Complex masks add CPU and memory work, particularly on video. `cliproom_set_color_mask` exposes the same action with a revision check and dry run.
