# Enhancement audit and remaining work

RoomSuite 3 builds on the 2.5.0 source associated with `efb00e09`. It adds shared color and presets, editable audio processing, creative and productivity improvements, and corresponding MCP workflows. Version 3.1 fixes grading-panel state, optimizes the shared CPU renderer, and warns about severely slow realtime exports. The matrix below records the scope and known limits; the exploratory brief includes capabilities that remain bounded or were deliberately deferred.

## Operational decisions

- Headless renders default to one active job and four waiting jobs; the queue is bounded and cancelled waiting requests are removed. Configure `CLIPROOM_RENDER_CONCURRENCY` (1–4) and `CLIPROOM_RENDER_MAX_QUEUE` (0–20). A full queue returns HTTP 429.
- File versions count toward storage and are retained until explicitly deleted, with a maximum of 20 per saved path and 10,000 total. Productivity saves warn when the prior version cannot be retained; other files require manual snapshots. Historical paths do not follow moves.
- Items moved to Shared files trash retain their original path, count toward storage, and remain until explicitly purged. Restores refuse an occupied destination and can use a different path whose parent exists. Trash is part of the normal workspace backup. The legacy permanent-delete endpoint remains available and cannot be undone.
- The editor and MCP preserve current project revision checks. PixelRoom's file-based MCP grade action writes a new file and requires the inspected SHA-256 revision; Cliproom's batch action requires the saved project's current revision. Reapplying an identical grade at the current Cliproom revision is a no-op.
- The repository already provides multi-Room MCP invocation. No orchestration layer, public marketplace or account service was added.

## Further validation and follow-up

1. Run the brief's physical low-end/mobile performance checks, including model memory, editing responsiveness and video export. The moving-video 1080p comparison in `PERFORMANCE.md` is a short desktop diagnostic, not a physical-device test. Advanced full-resolution grading remains CPU-bound; fast preview and every-frame export are available with the tradeoffs documented there.
2. Broaden speech recognition, proxy, audio handoff and rendering tests across real media, codecs and devices. Run representative Linux and macOS checks as well as the Windows installer regression.
3. Review the bounded feature and UI–MCP limitations in the matrix above, including static Cliproom masks, subset iCalendar support, OCR review and unsupported interchange objects, against the intended release scope.

The tests run on this machine are documented in the handoff response. Browser mobile emulation does not substitute for a physical mobile browser; a short synthetic moving-video sample does not prove codec or color-space parity generally.
